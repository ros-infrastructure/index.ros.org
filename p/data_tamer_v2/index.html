CHANGELOG

Changelog for package data_tamer

2.1.0 (2026-11-13)

  • MCAPSink and MCAPRingSink keep the page cache of the files they write bounded on Linux: every 32 MiB they start the writeback of the new data, wait for the previous 32 MiB to reach the disk and drop it from the cache, so about 96 MiB of a file is cached at most. A 2 GiB dump no longer leaves 2 GiB of dirty pages for the kernel to flush at once, which flooded the disk queue and stalled other processes on page faults. Closing a file now runs fsync(): stop(), stopRecording() and a rollover return once the file is on disk.
  • MCAPSink reports failed writes. It used mcap::FileWriter, whose fwrite() check is an assert, so a full disk produced a truncated file with no error. Now a failed write throws from onSnapshot() (counted in SinkWorker::errors()), and a failure while closing the file throws from stopRecording(), or from the onSnapshot() or restartRecording() that closed it. MCAPRingDump reports a failed fsync() or close() too.
  • The sink worker threads are named dt_sink_worker and the MCAPRingSink writer thread dt_ring_writer (Linux, macOS), for top -H, perf and debuggers.

2.0.0 (2026-10-24)

First release of the 2.x series, relative to 1.0.4. It breaks source and binary compatibility: rebuild every binary that links data_tamer, and read docs/MIGRATION.md, which gives the replacement for each removed API and lists the behaviour changes that compile without a warning. Readers need the 2.0 parser for files recorded by 2.0; it still reads 1.x files.

Breaking changes

  • The namespace is DataTamer2 (was DataTamer), the headers are in data_tamer_v2/ (were data_tamer/) and the standalone parser is data_tamer_v2/data_tamer_parser.hpp (was data_tamer_parser/data_tamer_parser.hpp). SerializeMe and DataTamerParser keep their names, inside an inline namespace v2.
  • DataSinkBase is replaced by DataSink, whose protected callbacks are onSchema(), onSnapshot(const SnapshotRef&) and the optional onStop() and onStart() (throw to report a failure), owned by a SinkWorker that runs the delivery thread. addChannel(), pushSnapshot(), storeSnapshot(), stopThread(), stopAcceptingSnapshots(), processQueuedSnapshots() and startAcceptingSnapshots() are gone: use SinkWorker::stop(), drain() and start(). To write data_tamer MCAP files from your own data, use sinks/mcap_encoding.hpp.
  • Sinks are created with MCAPSink::create(), ROS2PublisherSink::create(), DummySink::create() or SinkWorker::create<T>(), which return a std::shared_ptr<SinkWorkerOf<T>>: a SinkWorker whose sink() is the T (static cast, no dynamic_cast), converting to the std::shared_ptr<SinkWorker> that addDataSink() and addDefaultSink() take. worker->as<T>() reaches the sink through a plain SinkWorker (std::bad_cast for the wrong type). Passing std::make_shared<MCAPSink>(path), as in 1.x, to addDataSink(), removeDataSink() or addDefaultSink() fails with a static_assert that names MCAPSink::create() and SinkWorker::create<T>(). LogChannel::addDataSink() takes the worker and returns bool (false if it was attached already). MCAPSink::finishQueueAndStop() is removed (worker->stop()), restartRecording() no longer resumes a stopped worker, and DummySink has accessors (latestSnapshot(), schema(hash), ...) instead of public members.
  • Snapshot has no channel_name (use Schema::channel_name, matched by schema_hash), and schema_hash is uint64_t. DataSnapshot is removed.
  • takeSnapshot() returns a SnapshotResult instead of bool (accepted(result) replaces the bool). getActiveFlags() is removed: isEnabled(id) in the application, Snapshot::active_mask in a sink.
  • LogChannel::writeMutex() and the Mutex alias are removed: another thread writes registered variables inside scopedWrite().
  • LoggedValue: scalars are atomic and use set() and get() only. Structs and vectors keep getMutablePtr() and getConstPtr(), whose guards are not movable and have no operator bool and no mutex(). getLockedPtr() and the auto_enable parameter of set() are removed. A LoggedValue can't be moved or default-constructed.
  • RegistrationID is opaque: no first_index, fields_count or operator+=.
  • CustomSerializerT(std::string) is explicit, CustomTypeName<T>::get() is not constexpr, Schema::custom_types and custom_schemas are std::map (were std::unordered_map), and long double is a compile error. Removed: getPointerType(), SerializeMe::enable_if_same_t and the library's AddFieldToHash(), replaced by SchemaTextHash() and ComputeSchemaHash() (the parser keeps its own, for version 4 texts).
  • Parser: ParseSnapshot() loses its unused callback_custom parameter and is [[nodiscard]]; ParseSnapshotRecursive moves to DataTamerParser::detail and NullCustomCallback is removed; SnapshotView::schema_hash is uint64_t; BuilSchemaFromText() is a deprecated alias of BuildSchemaFromText(). The header needs a little-endian host and no longer includes <iostream>.
  • sinks/ros2_publisher_sink.hpp no longer includes the data_tamer_msgs headers.

  • MCAPSink reports failed writes. It used mcap::FileWriter, whose fwrite() check is an assert, so a full disk produced a truncated file with no error. Now a failed write throws from onSnapshot() (counted in SinkWorker::errors()), and a failure while closing the file throws from stopRecording(), or from the onSnapshot() or restartRecording() that closed it. MCAPRingDump reports a failed fsync() or close() too.

2.0.0 (2026-10-24)

First release of the 2.x series, relative to 1.0.4. It breaks source and binary compatibility: rebuild every binary that links data_tamer, and read docs/MIGRATION.md, which gives the replacement for each removed API and lists the behaviour changes that compile without a warning. Readers need the 2.0 parser for files recorded by 2.0; it still reads 1.x files.

Breaking changes

  • The namespace is DataTamer2 (was DataTamer), the headers are in data_tamer_v2/ (were data_tamer/) and the standalone parser is data_tamer_v2/data_tamer_parser.hpp (was data_tamer_parser/data_tamer_parser.hpp). SerializeMe and DataTamerParser keep their names, inside an inline namespace v2.
  • DataSinkBase is replaced by DataSink, whose protected callbacks are onSchema(), onSnapshot(const SnapshotRef&) and the optional onStop() and onStart() (throw to report a failure), owned by a SinkWorker that runs the delivery thread. addChannel(), pushSnapshot(), storeSnapshot(), stopThread(), stopAcceptingSnapshots(), processQueuedSnapshots() and startAcceptingSnapshots() are gone: use SinkWorker::stop(), drain() and start(). To write data_tamer MCAP files from your own data, use sinks/mcap_encoding.hpp.
  • Sinks are created with MCAPSink::create(), ROS2PublisherSink::create(), DummySink::create() or SinkWorker::create<T>(), which return a std::shared_ptr<SinkWorkerOf<T>>: a SinkWorker whose sink() is the T (static cast, no dynamic_cast), converting to the std::shared_ptr<SinkWorker> that addDataSink() and addDefaultSink() take. worker->as<T>() reaches the sink through a plain SinkWorker (std::bad_cast for the wrong type). Passing std::make_shared<MCAPSink>(path), as in 1.x, to addDataSink(), removeDataSink() or addDefaultSink() fails with a static_assert that names MCAPSink::create() and SinkWorker::create<T>(). LogChannel::addDataSink() takes the worker and returns bool (false if it was attached already). MCAPSink::finishQueueAndStop() is removed (worker->stop()), restartRecording() no longer resumes a stopped worker, and DummySink has accessors (latestSnapshot(), schema(hash), ...) instead of public members.
  • Snapshot has no channel_name (use Schema::channel_name, matched by schema_hash), and schema_hash is uint64_t. DataSnapshot is removed.
  • takeSnapshot() returns a SnapshotResult instead of bool (accepted(result) replaces the bool). getActiveFlags() is removed: isEnabled(id) in the application, Snapshot::active_mask in a sink.
  • LogChannel::writeMutex() and the Mutex alias are removed: another thread writes registered variables inside scopedWrite().
  • LoggedValue: scalars are atomic and use set() and get() only. Structs and vectors keep getMutablePtr() and getConstPtr(), whose guards are not movable and have no operator bool and no mutex(). getLockedPtr() and the auto_enable parameter of set() are removed. A LoggedValue can't be moved or default-constructed.
  • RegistrationID is opaque: no first_index, fields_count or operator+=.
  • CustomSerializerT(std::string) is explicit, CustomTypeName<T>::get() is not constexpr, Schema::custom_types and custom_schemas are std::map (were std::unordered_map), and long double is a compile error. Removed: getPointerType(), SerializeMe::enable_if_same_t and the library's AddFieldToHash(), replaced by SchemaTextHash() and ComputeSchemaHash() (the parser keeps its own, for version 4 texts).
  • Parser: ParseSnapshot() loses its unused callback_custom parameter and is [[nodiscard]]; ParseSnapshotRecursive moves to DataTamerParser::detail and NullCustomCallback is removed; SnapshotView::schema_hash is uint64_t; BuilSchemaFromText() is a deprecated alias of BuildSchemaFromText(). The header needs a little-endian host and no longer includes <iostream>.
  • sinks/ros2_publisher_sink.hpp no longer includes the data_tamer_msgs headers.

  • Sinks are created with MCAPSink::create(), ROS2PublisherSink::create(), DummySink::create() or SinkWorker::create<T>(), which return a std::shared_ptr<SinkWorkerOf<T>>: a SinkWorker whose sink() is the T (static cast, no dynamic_cast), converting to the std::shared_ptr<SinkWorker> that addDataSink() and addDefaultSink() take. worker->as<T>() reaches the sink through a plain SinkWorker (std::bad_cast for the wrong type). LogChannel::addDataSink() takes the worker and returns bool (false if it was attached already). MCAPSink::finishQueueAndStop() is removed (worker->stop()), restartRecording() no longer resumes a stopped worker, and DummySink has accessors (latestSnapshot(), schema(hash), ...) instead of public members.
